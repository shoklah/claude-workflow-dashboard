# Server fixes F31 and F32 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A step kind's cost reads unknown until a priced model, and a counted skill outcome leaves the server as one label.

**Architecture:** Two server functions change their output: `stepSums` (`packages/server/src/views/steps.ts`) and `skillOutcomeLabel` (`packages/server/src/views/runs.ts`). check:real reads a null step cost as the reporter's 0. The web app changes no code: only its invented fixtures, stories and the screen baselines carry the new text.

**Tech Stack:** TypeScript, Vitest, Storybook (chromium), Playwright in the screens container.

**Spec:** `docs/superpowers/specs/2026-11-17-server-f31-f32-design.md`

## Global Constraints

- Labels, verbatim: `found something` when any count of a counted outcome isn't 0, `found nothing` when every count is 0.
- A counted outcome is a non-null object (arrays already return earlier) whose every value is a number; any other object stays `–`.
- A step kind's cost is null until one of its dispatched models has a non-null `cost`; then the sum of the non-null costs. Simplify's stays null.
- check:real compares a step's cost as `(cents(row.cost) ?? 0) !== (cents(want.cost) ?? 0)`: null reads as 0 on both sides, so simplify's null against the reporter's null still agrees.
- Invented data only; CLAUDE.md's Code conventions (both new lines at the skill outcome rule) already state the rules.

## Review Focus

- A step kind with dispatches whose `models` all have `cost: null`: cost null, tokens still summed (Task 1).
- A step kind with one priced and one unpriced model: cost is the priced one's alone (Task 1).
- A counted outcome with only `skipped` above 0: `found something` (Task 2).
- An object outcome with a non-number value (`{ applied: 'x' }`): `–`; an empty object `{}`: `found nothing`, as the reporter (Task 2).
- check:real on an export whose step has no priced dispatch: no `steps` difference (Task 1).
