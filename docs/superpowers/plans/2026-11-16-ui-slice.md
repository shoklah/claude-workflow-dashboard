# UI Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle all twelve screens of the dashboard to `DESIGN.md` and the `ui` kit's floor, as the approved captures show, with contrast proved from the tokens.

**Architecture:** A presentation-only change in `packages/web`. Part 1 lands the shared patterns (tuned tokens and their contrast test, `Panel.tsx`, `Num.tsx`, `format.ts` helpers, the adapted shared components, the shell's mobile menu) as one pull request. Part 2 restyles the screens one task each on those patterns, removes what nothing uses any more and regenerates the baselines, as a second pull request. Each file is ported from the local reference branch `claude/ui-slice-mock` under tests written first.

**Tech Stack:** TypeScript, React, Tailwind, shadcn/ui, ECharts, Storybook (stories run by Vitest in chromium), Playwright with axe.

**Spec:** `docs/superpowers/specs/2026-11-16-ui-slice-design.md`. Captures: `docs/design/2026-11-16-ui-slice/<screen>-<1440|375>-<dark|light>.jpg`.

## Global Constraints

- Nothing outside `packages/web`, `DESIGN.md`, `CLAUDE.md` and `docs/` changes: no API, view, schema or fixture-data change.
- The reference for a file is `git show claude/ui-slice-mock:<path>`. **The spec, the captures and `CLAUDE.md`'s conventions win over the mock's code**: the mock was never reviewed, so its shortcuts are not carried over (each task lists the ones known). Never merge or cherry-pick from that branch; do not port `mock-capture.mjs` or `mock-menu.mjs`.
- No new dependency and no new shadcn component.
- Tokens live only in `packages/web/src/index.css`, light and dark; no colour, type size, radius or shadow literal in a component.
- Text directly on the backdrop is primary ink: no `text-muted-foreground` and no `WARNING_INK` outside a panel, table container, dialog, popover or notice bar.
- A table cell holds a plain number under a header naming its unit; the only adaptive cell is a session's length (`formatLength`).
- Fixtures and story data are invented.
- Relative imports carry their `.ts`/`.tsx` extension, type-only imports use `import type`, code stays erasable-only TypeScript.
- Every new or adapted component has stories in the same task; a story's interaction test is the UI's failing test.
- Every task ends green on `pnpm -r typecheck`, `pnpm vitest run` and `pnpm build`.
- Screens baselines are not regenerated per task: Tasks 7 and 21 do it once per part, in the container.
- Charts are written with the `dataviz` skill loaded.
- Where the spec's wording of a header or a term and the approved capture's differ ("Recommended by stage" against "Recommended, by stage"), the capture's words win.
- The scroll cue shows in no screenshot this run takes: the kit's screens check and `toHaveScreenshot` disable animations, which cancels a scroll-timeline animation, and the approved 375 px captures were taken with animations on. The cue is proved only by Task 3's e2e check; the session says so in every `kit-reviewer` dispatch, so a missing cue in a 375 px shot is not a finding.
- The approved captures were taken with the panels' backdrop blur on, which Task 1 removes: a panel in this run's shots shows the backdrop a little sharper and less saturated than its capture, and that is not a finding.
- Every Playwright command of a task runs on the task's own port, `E2E_PORT=45<task number, two digits>` (Task 4: `E2E_PORT=4504`), so the tasks of a wave don't fight over 4399.

## Review Focus

1. A session of 0 minutes, under an hour, and of exactly one day: `formatLength` gives "0 min", "45 min", "1 d 0 h" (1439.6 minutes rounds to a day). Test in Task 2.
2. A model id of an unknown shape ("<synthetic>", "opus", "-", "", null): `modelLabel` gives the id unchanged, "Opus", and null for the last three; never throws. Test in Task 2.
3. A warning with no "WARN:" prefix, one whose lead names another branch, and one that is only its prefix: `warningBody` keeps the first, keeps the other branch's lead, and returns "" for the last. Test in Task 2.
4. A token missing or renamed in `index.css`: the contrast test fails on a count assertion (four orbs, three stops, four blobs) instead of passing on an empty set. Test in Task 1.
5. A reporter information line with no ": ", and one with two: Compliance shows the first under the label "Line N" and splits the second at the first ": " only. Test in Task 14.

- [ ] **Step 1: Write the failing test** in `contrast.test.ts`. It imports the theme as text (`import css from '../index.css?raw'`), reads the declarations of the `:root {` and `.dark {` blocks, and computes WCAG contrast with plain arithmetic (sRGB relative luminance; `over(top, alpha, bottom)` per channel). No browser API.

```ts
// Per mode: the backdrop colours are each gradient stop (light: --background), and each orb's colour at its opacity
// over each stop. A surface is --panel over a backdrop colour with each end of --panel-sheen over that; the header
// band adds --secondary, and `hover` adds --accent (the menu's current page, a hovered button). A table row's own
// hover is --muted at 50%, lighter than the band, so the band covers it.
// Nothing filters what is behind a panel, so these colours are the ones drawn. A panel's backdrop-filter was also
// recomputed on every scroll frame over the fixed backdrop, which made scrolling lag.
test('no backdrop-filter', () => expect(css).not.toMatch(/backdrop-filter/));
test('the theme parses to the expected backdrop', () => {
  expect(dark.stops).toHaveLength(3);
  expect(dark.orbs).toHaveLength(4);
  expect(light.orbs).toHaveLength(4);
});
for (const mode of [light, dark]) {
  test(`${mode.name}: primary ink on every backdrop colour`, () => expect(worst(mode.foreground, mode.backdrop)).toBeGreaterThanOrEqual(4.5));
  test.each(['panel', 'band', 'hover'] as const)(`${mode.name}: primary, secondary and warning ink on the %s`, (surface) => {
    for (const ink of [mode.foreground, mode.mutedForeground, mode.warningInk]) expect(worst(ink, mode[surface])).toBeGreaterThanOrEqual(4.5);
  });
  test(`${mode.name}: notice ink on the notice bar over every backdrop colour`, () => expect(worst(mode.noticeInk, mode.noticeBar)).toBeGreaterThanOrEqual(4.5));
  test(`${mode.name}: each shade step's ink`, () => { /* --on-shade-N on --shade-N, N = 1..5; --on-shade-zero on --shade-zero over mode.panel only: heatmap rows don't hover and its cells are never in the header band */ });
}
```
