# Side Menu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the shell's flat menu into a full-height sticky rail with named sections, icons, edward's brand, and showing mode, Refresh and the import time at its foot.

**Architecture:** A presentation-only change in `packages/web/src/layout`. A new `Brand` draws the name and mark; `Menu` renders its one list of pages as sections; `Shell` becomes the sticky rail (brand, scrolling menu, foot) with no header row from 768 px, and keeps today's top row under it. The under-768 controls and the rail's are both rendered and one is hidden by breakpoint (`display: none`), as the mockup does.

**Tech Stack:** TypeScript, React, Tailwind, shadcn/ui (lucide icons), Storybook (stories run by Vitest in chromium), Playwright with axe.

**Spec:** `docs/superpowers/specs/2026-11-17-menu-design.md`. Captures: `docs/design/2026-11-17-menu/menu-*.jpg`, the mark's source `docs/design/2026-11-17-menu/mark.svg`.

## Global Constraints

- Nothing outside `packages/web`, `DESIGN.md`, `CLAUDE.md` and `docs/` changes: no API, view, schema or fixture-data change. "Imported" shows `lastGoodImportAt`, which `/api/status` already returns.
- No new dependency and no new shadcn component: lucide, Outfit (weights 300 and 700) and the installed `Dialog` are there.
- The reference for the look is `git show claude/menu-mock:packages/web/src/layout/Menu.tsx` and `.../Shell.tsx`. **The spec, the captures and `CLAUDE.md`'s conventions win over the mock's code**; never merge or cherry-pick from that branch, and carry over none of its `variant()`, `?brand=`, question names or `[&>div>div]` child selectors.
- Nothing is renamed but the tab title, the favicon and `DESIGN.md`'s name: not the README, package names, data folder or launchd label.
- `DESIGN.md` holds: no panel inside a panel, secondary ink only on a panel, dialog or notice bar, no `backdrop-filter`, hover changes instant, buttons are pills.
- A menu entry's icon never carries state: 16 px, primary ink, `aria-hidden`. The rail's only colour is the mark and, while showing mode is on, its amber bar.
- The rail and the dialog render the same `Menu`; there is no second list of pages.
- Colours live only as tokens in `packages/web/src/index.css`; the favicon file alone holds fixed colours.
- Relative imports carry their `.ts`/`.tsx` extension, type-only imports use `import type`, code stays erasable-only TypeScript.
- Every new or adapted component has stories in the same task; a story's interaction test is the UI's failing test. Story data is invented.
- The under-768 controls stay in the DOM from 768 px, hidden: stories and e2e find a control by role (`getByRole`), which skips hidden elements, never by `getByText`.
- Every task ends green on `pnpm -r typecheck`, `pnpm vitest run` and `pnpm build`.
- Screens baselines are not regenerated per task: Task 4 does it once, in the container.
- Every Playwright command of a task runs on the task's own port, `E2E_PORT=46<task number, two digits>` (Task 2: `E2E_PORT=4602`).

## Review Focus

1. `/favicon.svg` is answered by the server's fallback to `index.html` instead of the SVG: the tab shows no icon and nothing fails. Test in Task 1.
2. A phone shorter than the menu (375 by 480 px): the dialog scrolls inside itself and its last link, "Models and advisor", can be reached. Test in Task 2.
3. Showing mode on with several long project names in the 224 px rail: the bar wraps inside the rail; it never widens it or pushes Refresh out. Test in Task 3.
4. The status still loading, or the server unreachable: the rail shows the brand, the menu and Refresh, no "Imported" line and no stale time. Test in Task 3.
5. An import that failed before any good one (`error` set, `lastGoodImportAt` null): the banner says both (`StatusBanner.stories.tsx`'s existing `FailedBeforeAnyImport`), and the rail shows no "Imported" line, on the same `lastGoodImportAt` test Task 3's `NeverImported` asserts.
