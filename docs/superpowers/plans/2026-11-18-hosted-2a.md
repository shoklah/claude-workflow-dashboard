# Hosted edward, plan 2a: collector, accounts, sign-in, request rules and tokens

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A hosted edward that friends sign in to with GitHub (invite-only), each account with its own SQLite file, fed by a collector on their laptop through a collector token; local mode unchanged.

**Architecture:** `config.json`'s `mode` picks `local` (today), `collector` or `hosted`. Hosted mode keeps one Hono app: `createApp`'s one middleware applies hosted mode's `Host`/`Origin` rules, resolves the caller (a session cookie, or a bearer token on `/api/collect*` only) and sets the request's database (`c.var.db`), so every route block reads its account's file and views stay as they are. A small accounts database (`accounts.sqlite`, its own Drizzle schema and migrations) holds invites, accounts, sessions and tokens, secrets stored as SHA-256. The collector reuses `runReporter`, `startTriggers` and `createQueue` and sends the export gzipped; the server imports it with `importReport` into the account's file.

**Tech Stack:** Node >= 22.18 running TypeScript sources, Hono (`hono/cookie`, `hono/body-limit`), Drizzle over better-sqlite3, zod, React with TanStack Router and Query, shadcn/ui, Vitest, Storybook, Playwright, Docker.

**Spec:** `docs/superpowers/specs/2026-11-18-cross-platform-and-hosted-design.md`, "Phase 2: the collector", "Phase 3: the hosted mode" (sign-in, request rules, account resolution, storage, collector tokens, deployment, refresh and status, display names) and "Screens". Plan 2b (`2026-11-18-hosted-2b.md`) holds viewers and the account switcher, the per-account labeller, the admin settings, account deletion and `account:import`.

## Global Constraints

- Local mode is unchanged: no login, `127.0.0.1` only, today's request rules, Refresh shown; every existing test passes unmodified except where a task says it changes.
- Hosted settings come from the data folder's `.env` only: `EDWARD_PUBLIC_HOST` (the public hostname), `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `EDWARD_ADMIN` (the admin's GitHub login). `EDWARD_SECRET` is plan 2b's.
- The collector's token is `EDWARD_TOKEN` in the data folder's `.env`, never in `config.json`, the repo or a log; the collector's server URL is `config.json`'s `server`.
- Identity is GitHub's numeric user id (`accounts.id`), never the login; an account's file is `<dataDir>/accounts/<id>.sqlite`, today's schema, migrated and `rebuildDerived` when first opened in a process, handles kept in a map.
- A session is 32 random bytes in cookie `edward_session` (`HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`, 30 days), stored as its SHA-256 hex; sign-out deletes it. A collector token is `ed_` + base64url of 32 random bytes, shown once, stored as its SHA-256 hex; it resolves only on `/api/collect*`.
- Hosted request rules, only in `createApp`'s one middleware: `Host` equals `EDWARD_PUBLIC_HOST`; any method but GET and HEAD on a browser route needs `X-Dashboard-Refresh: 1` and `Origin` equal to `https://<EDWARD_PUBLIC_HOST>` (sent and equal: a missing `Origin` is refused in hosted mode); `/api/collect*` takes `Authorization: Bearer <token>` and no cookie, `Origin` or refresh header. No `Access-Control-*` header anywhere.
- No caller: `/api/*` answers 401 with no body; a page answers a 302 to `/signin`. Open without a caller: `/signin`, `/auth/*`, `/assets/*`, `/favicon.svg`.
- Never in a response, a log line or an error text: a token, session ID, OAuth code or access token, `GITHUB_CLIENT_SECRET`, or another account's data. Error texts are fixed messages or statuses, as today.
- Hosted mode has no `aliases` (`{}`), no Refresh route (404) and no labeller (2b adds it); `/api/status` is the caller's account's.
- One machine per account: an export whose cursor's state id differs from the stored cursor's is refused with 409 and a fixed message; "Reset collector" clears the stored cursor.
- `/api/collect` takes a gzipped body (`Content-Encoding: gzip`) of at most 32 MB, unzipped to at most 512 MB.
- Erasable-only TypeScript, relative imports with `.ts`, `import type` for types; migrations only from `drizzle-kit generate`.
- Each task adds or changes its `CLAUDE.md` `## Code conventions` lines (one line each, the rule only) in the same commit.

## Review Focus

1. **A cookie or token of account A reaching account B's data** (a route that keeps reading a module-level database, a cached handle keyed wrongly, a token used on a page route): A's request returns only A's rows; tested in Task 3 (two accounts, every page route) and Task 5 (a token imports into its own account's file only).
2. **A secret written somewhere it shouldn't be** (a raw token or session ID in `accounts.sqlite`, the OAuth code or access token or `client_secret` in a redirect URL, a log line or error text): tested in Task 1 (the file's bytes hold no raw secret), Task 4 (redirects and logs) and Task 6 (the collector's log on a send failure holds the status only).
3. **A second machine's export** (another state id) marking the first machine's units missing: refused with 409 before anything is stored; tested in Task 5.
4. **OAuth return with a forged or missing `state`, a GitHub error, or a GitHub API failure**: no account, no session, a redirect to `/signin?error=failed`; tested in Task 4.
5. **A local install after this change**: same `Host` rule, same POST rule, no 401, Refresh present; the existing `app.test.ts` passes unchanged and Task 3 adds a test that a session cookie is ignored in local mode.

## Spec flags (to the owner with the plan)

1. **Imports run inline in `POST /api/collect`**, not through a queue: better-sqlite3 is synchronous, so imports are already one at a time across accounts and `/api/status`' `importing` is always false in hosted mode. The spec's "one import queue across accounts" holds in effect; no queue object is built.
2. **The machine's state id isn't stored separately:** it is the stored cursor's own state id, so "Reset collector" clears the cursor (the next export is full) and `account:import`'s copied cursor carries it, as the spec wants.
3. **The kit's screens check can't sign in**, so `/account` (and 2b's `/admin`) is checked by the hosted e2e and screen tests, which sign in through dev:fixtures' stub GitHub; the kit checks run on `/signin` only.
4. **A missing `Origin` on a hosted browser POST is refused** (local mode allows it): every browser sends `Origin` on a POST, and the hosted server is public.
