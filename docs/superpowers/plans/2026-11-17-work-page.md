# Work page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Goals and changes above runs and sessions: a Work page (Changes, Runs and Sessions views) that replaces the Runs and Sessions menu entries, a page per goal and per change with a session graph, and run titles wherever a run is named.

**Architecture:** The reporter's new facts are declared in `report.ts` and stored as they come (no migration). One pure module, `packages/server/src/views/work.ts`, builds the levels (changes, goals, a session's change and step) and the Work, change and goal views; the Runs, Sessions and run page views read a unit's change and goal from it. The web app adds `work/` (the page, the two detail pages, `ChangesTable`, `SessionGraph` with its pure layout in `work/graph.ts`) and turns the Runs and Sessions pages into views of `/work`.

**Tech Stack:** TypeScript end to end, zod, Hono, Drizzle over SQLite, React with TanStack Router and Query, Tailwind and shadcn/ui, Vitest, Storybook, Playwright with axe.

**Spec:** `docs/superpowers/specs/2026-11-17-work-page-design.md` (approved 2026-11-17). Read it in full before any task; the plan argues from it and does not repeat it.

## Global Constraints

- The reporter's field names, from the workflow's approved design (`shoklah/gilead`, branch `claude/hungry-bell-a8829d`, `docs/superpowers/specs/2026-11-17-work-page-facts-design.md`), JSON `version` 1:
  - on a run entry (plan records included): `headline` (string or null), `goal` (string or null), `spec` (`{project, path}` or null; `project` an absolute path, `path` under that project's root). The existing run `title` stays the session's title.
  - on a session entry: `goal`, `spec` (same shape), `started_by` (`{key, how}` or null; `key` the reporter's session key, equal to `sessionKey`; `how` `'started'` or `'handoff'`).
  - on `context`: `handoff_to` (already declared).
- Every new schema field is declared as `report.ts` declares the others (`.nullish()` through its helpers); with none of them the page works (spec, "Before the facts arrive").
- No migration and no new dependency; the graph draws as `RunFlow` does (HTML boxes over an `aria-hidden` SVG), no graph library.
- Every name, title, goal and spec file name from units is masked with `maskText` under a scope; each new or changed view's tests run `leaks` over a showing-mode response.
- Fixtures are invented; no real project, path, branch or session ID.
- Copy is the spec's, verbatim: "Runs recorded before goals existed show under No goal.", "4 sessions in this period belong to no change." (the count varies), "No work in this period. A change shows here once one of its sessions or runs is imported.", "Nothing matches these filters.", "This goal isn't in the data any more." (and "This change isn't in the data any more."), "Couldn't load the changes." (the goal, the change), "Loading the changes…" (the goal, the change), the dash read "no design", "started by you", "no goal".
- `check:real`'s Work line (Task 11) waits until the workflow's PR exporting these fields is merged; Tasks 1 to 10 do not.

## Review Focus

1. **A starter chain that loops or names a session not stored** (a `started_by` key matching no stored session, or A started B started A): the graph draws no edge for a missing starter, never loops, and every session still gets a column. Tests in Task 4 (missing starter) and Task 8 (loop).
2. **Markup in a headline, goal name or spec path** (the fixture's `<img onerror>` branch): shown as text everywhere, never as HTML, in tables, graph boxes and `RunLink`. Tests in Task 6's and Task 8's stories.
3. **A goal or change Work doesn't list in showing mode** (its home project hidden, even when one of its units is shown), opened by its URL: answers as missing (404), the same as an unknown key, so the page shows "This goal isn't in the data any more." and leaks nothing; a shown unit of such a change shows no change or goal, and a graph box names it only as "Another change" or "Another goal" (the owner's ruling, 2026-11-17). Tests in Tasks 4 and 5.
4. **A spec `project` given as a worktree path** (`…/.claude/worktrees/x`): folded through `projectRoot`, so it keys the same change as the main checkout. Test in Task 2.
