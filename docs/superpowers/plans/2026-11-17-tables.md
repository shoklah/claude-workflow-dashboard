# Lists of Items Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every list of items (Runs, Sessions, Context's runs and sessions, Compliance's warnings, findings and strengths) shows a short first glance that sorts by header click, pages of 10, and a row that opens in place to the rest, with narrow columns folding into the opened row.

**Architecture:** A presentation-only change in `packages/web`. A new `DataList` (with `SortHead` and `Pager` beside it, on TanStack Table 9's sorting and pagination features) takes a list's columns and opened-row facts. Each of the six lists becomes a thin set of column and fact definitions over it. The fold is a container query on `DataList`'s wrapper (`@container`, columns `hidden @3xl:table-cell`).

**Tech Stack:** TypeScript, React, Tailwind 4 (container queries are core), shadcn/ui `Table`, `@tanstack/react-table` 9.3.1, Storybook (stories run by Vitest in chromium), Playwright with axe.

**Spec:** `docs/superpowers/specs/2026-11-17-tables-design.md`. Captures: `docs/design/2026-11-17-tables/tables-*.jpg`.

## Global Constraints

- Nothing outside `packages/web` changes: no API, view, schema or fixture-data change. The rows and facts each list holds stay the same, only split between first glance and opened row.
- No new dependency and no new shadcn component.
- The reference for the look is `git show claude/tables-mock:packages/web/src/components/DataList.tsx` (and `ListTable.tsx`, and each adapted list on that branch). **The spec, the captures and `CLAUDE.md`'s conventions win over the mock's code.** Never merge or cherry-pick from that branch. Carry over none of its `?long` padding (`mockLong.ts`, the `data:` line), `?variant=b`, `MOCK` comments or `SEVERITY_RANK`.
- `PAGE_SIZE` = 10. Pager text: `` `${first}–${last} of ${total}` `` (an en dash), buttons "Previous" and "Next". Its `nav` is named `` `${label} pages` ``.
- The fold is the list's container under 768 px (`@3xl`), never a viewport breakpoint (`sm:`, `md:`).
- Sorting cycles ascending, descending, then the list's own order (TanStack `sortDescFirst: false`, with the third click clearing the sort). Unknown values sort last in both directions (`sortUndefined: 'last'`). A column whose first known value is a number sorts `basic`, else `alphanumeric` (F2 before F10). A time column's `value` is `parseTime(t)?.getTime() ?? null`, so times sort by value.
- A row's opened facts are `Pairs text`, at most `max-w-3xl`, empty ones (null or `''`) left out: a fact returns null when its value is unknown, and only a known value goes through `Num` (zero still shows, muted). Folded columns come first, in column order, under their header text. Today's marks stay with their fact or cell: Runs' muted "before steps" mark in Branch, `WARNING_INK` on Sessions' Never loaded, Startup "Missing" and Warnings, and on Context's Past the cap.
- The toggle sits in the first column that doesn't fold. Where that column's `text(row)` gives a string, the cell is `RowToggle` around that text; otherwise (a `RunLink`) a chevron-only button with `aria-expanded`, named `` `Details of ${name(row)}` ``, sits before the cell. A list whose rows have no facts beyond the folded columns shows its button only while folded (`@3xl:hidden`).
- Open rows are a set keyed by `rowKey` (never the shown index), so a row stays open across sorting and pages. The list goes back to page 1 when the sequence of row keys changes, never on a new array holding the same rows (a parent's re-render, Findings' Measure switch).
- Relative imports carry their `.ts`/`.tsx` extension, type-only imports use `import type`, code stays erasable-only TypeScript.
- Every adapted list keeps stories for its empty and full states. A story's interaction test is the UI's failing test, and its data is invented (`src/test/*.ts`).
- Stories run in Vitest's browser at 414 px, where every list folds: a list story that checks the full first glance renders in a 1000 px wrapper (a `width(px)` decorator, as `RunFlow.stories.tsx` has). Stories and e2e find controls by role; folded columns stay in the DOM, hidden, so a test checks a header with `toBeVisible`/`not.toBeVisible`, never by counting `columnheader`s in the DOM.
- Every task ends green on `pnpm -r typecheck`, `pnpm vitest run` and `pnpm build`.
- The failing-test check runs a task's story files only, passed with `--test-file` (stories don't match its pattern); `shell.spec.ts` changes pass at the base and never go in it.
- Screens baselines are not regenerated per task: Task 6 does it once, in the container.
- Every Playwright command of a task runs on the task's own port, `E2E_PORT=47<task number, two digits>` (Task 2: `E2E_PORT=4702`).

## Review Focus

1. A filter or a step selection that leaves fewer rows than the current page's start (page 3 of findings, then Severity "Critical" with 4 rows): the list shows page 1, never an empty page. Test in Task 1 (`RowsChangeResetsPage`, and `SameRowsKeepPage` for a re-render with a new array of the same rows).
2. Two rows whose first-glance values are equal (the same branch run twice): opening one opens only that one, and it stays open after a sort. Test in Task 1 (`OpensInPlace`, `rowKey` not the shown name). Two findings with a null id in one run get distinct keys (Task 5).
3. A column whose value is unknown for some rows (a run with no cost): those rows sort last both ascending and descending. Test in Task 1 (`Sorts`).
4. The last, partial page: "21–24 of 24", Next disabled, Previous enabled. Test in Task 1 (`Pages`).
5. A list at a 768 px window, beside the rail: no list region scrolls sideways (Runs' did by 279 px in the mock). Test in Task 1 (`shell.spec.ts`'s loop over every page at 375, 768 and 1440 px).
