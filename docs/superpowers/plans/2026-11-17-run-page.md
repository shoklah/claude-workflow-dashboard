# Run Page (the run drawn as a graph) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Redraw `/runs/:key` around one drawing, the run as a graph, with the selected step's detail under it, two findings tables (Problems, Strengths) that follow the selection, Left for later, and the rest folded.

**Architecture:** `runView` gains the facts the graph draws (a step's model, effort and kit, a wave's conflicts, groups in running order); a new `runPageView` in `views/run.ts` calls it and adds the run's surroundings (its session, neighbours, offers, later fixes, agents, main session, phases), so the Findings view, which also calls `runView`, is untouched. Both mask under showing mode. On the web, one pure module (`runs/flow.ts`) turns the timeline into units and positions for three shapes (flat, wrapped, upright); `RunFlow` draws them with SVG paths and HTML buttons; `RunPage` holds the one selection and filters the tables with it. No new dependency.

**Tech Stack:** TypeScript, Hono, zod, React, TanStack Query and Table, Tailwind, shadcn/ui, lucide, Vitest (stories in chromium), Storybook, Playwright with axe.

**Spec:** `docs/superpowers/specs/2026-11-16-run-page-design.md`, with its captures in `docs/design/2026-11-16-run-page/`. Read both before any task. The spec and the captures win over this plan's wording and over the mock's code.

**Base:** written against the UI slice's part 2 at `claude/ui-slice-screens` `bbf53a2` (unmerged when this was written). Implementation starts on a branch cut from `main` once part 2 has merged, with this branch's commits (spec, captures, plan) on it. Before Task 1 the planning session diffs the merged `main` against `bbf53a2` and corrects any task it touches; an implementer who finds a named file, export or signature different from this plan reports `NEEDS_CONTEXT` instead of guessing.

**Mock:** the reference build is the local branch `claude/run-page-mock` (`git show claude/run-page-mock:packages/web/src/runs/RunFlow.tsx`, `…/RunPage.tsx`, `…/FindingsTable.tsx`). It is ported under tests, never merged or copied whole; it was built before part 2, its `mock` response field is unmasked, and it has the known flaws this plan names. Ported code is judged as new code.

## Global Constraints

- No new dependency. React Flow stays Home's diagram only.
- Every fact comes from the stored units through `runView` (`packages/server/src/views/runs.ts`) and `runPageView` (`views/run.ts`), masked there under showing mode and checked with `leaks`; the route only reads the database and calls it. Nothing is parsed from logs or transcripts here.
- Fixtures, stories, tests and captures hold invented data only.
- Tokens only from `packages/web/src/index.css`; page structure from `components/Panel.tsx`; formatting and labels from `lib/format.ts` (no label map or class constant inside a component); relative imports carry `.ts`/`.tsx`; erasable-only TypeScript.
- Every new or changed component has stories for its empty and full states (loading and error where it fetches); a story with an interaction test is the UI's failing test. Story fixtures live in `packages/web/src/test/runs.ts`.
- The graph never scrolls sideways and never scales its text; the page never scrolls sideways from 375 px up.
- Colour never carries a state alone: every orange, amber or green mark comes with a word, a count or an icon.
- Show, don't tell (`DESIGN.md`): the only explanatory texts are the ones the spec keeps (the hint, the states' lines, the "Later fixes" tooltip). Add none.
- Where the kit's floor and the approved captures disagree (the arc's "fix-checker ×2", "agent · model, effort" in the detail's column heads), the captures win; say so in the report.
- Every task ends green on `pnpm -r typecheck`, `pnpm vitest run` and `pnpm build`. Tasks 4 to 8 change `/runs/:key`, so each also runs `E2E_PORT=<free port> pnpm --filter @cwd/web exec playwright test --project=checks --project=checks-dark e2e/runs.spec.ts e2e/shell.spec.ts e2e/showing.spec.ts`, and the kit's checks. Screenshot baselines are regenerated once, in Task 8 (the run page's, and the Findings page's that Task 6's fixture change moves): between Tasks 4 and 8 `pnpm test:screens` is expected to differ on those two pages and is not run.
- Commit after each task's last step, one commit per task unless a step says otherwise.

## Review Focus

1. **A rank with more than three boxes on a phone** (a wave of three tasks, each with a kit review: six boxes). Expected: no overflow and no box too narrow to read; the rank stands in lines of at most three. Test in Task 3.
2. **A finding with more verdicts than its step has fix-check rounds**, or a verdict or outcome string the app doesn't know. Expected: every verdict shown, one column per verdict, an unknown one named through `countName` in the warning ink, never blank. Test in Task 5.
3. **A run with nothing around it**: no times, no window (cost and session unknown), no other run on its branch, no later fix. Expected: pills without a time, dashes in the header, a chain of the one box. Test in Task 7.
4. **A run whose steps name a wave or task the record's `waves` doesn't list**, or a wave with no step yet. Expected: every step drawn exactly once, a stepless wave drawn after the groups that have steps. Test in Task 1.

- Produces:
  ```ts
  /** One review with its fix rounds: a box of the graph. */
  export type Unit = { id: string; name: string; task: number | null; wave: string | null; kit: boolean;
    review: TimelineStep | null; rounds: TimelineStep[]; findings: FindingRow[] };
  export type Stage = { kind: TimelineGroup['kind']; at: string | null; parallel: Unit[]; then: Unit[]; conflicts: number };
  export function stagesOf(timeline: TimelineGroup[]): Stage[];
  export function unitsOf(stages: Stage[]): Unit[];                       // every unit, in drawing order
  export function leftOf(unit: Unit): [Outcome | 'none', number][];       // deferred, to_owner, open, declined, ruled, none; non-zero only
  export function stuck(unit: Unit): boolean;                             // its last round left `open` or `not_proportionate`
  export function strengthsOf(unit: Unit, strengths: StrengthRow[]): StrengthRow[];

  export type Shape = 'flat' | 'wrapped' | 'upright';
  type Rect = { x: number; y: number; w: number; h: number; row: number };
  export type Placed = Rect & (
    | { kind: 'unit'; unit: Unit }
    | { kind: 'pill'; end: 'start' | 'end'; at: string | null }
    | { kind: 'conflicts'; count: number }
    | { kind: 'chip'; unit: Unit; outcome: Outcome | 'none'; count: number }
    | { kind: 'arc'; unit: Unit });                                       // the loop's label, over its box
  /** `lead`: a straight run before the curve. `fade`: a straight run to or from the panel's side. */
  export type Anchor = { x: number; y: number; lead?: number };
  export type Edge = { from: Anchor; to: Anchor; fade?: 'out' | 'in'; head: boolean };
  export type Layout = { shape: Shape; width: number; height: number; rows: number; placed: Placed[]; edges: Edge[] };
  export const WRAP_MIN: number;   // the narrowest panel that wraps: four boxes with their gaps
  export function layout(stages: Stage[], avail: number | null): Layout;  // null: not measured yet, flat
  ```

    /** No two placed things overlap, and no edge's curve passes over one: the curve lies between its two leads. */
    function clear({ placed, edges, shape }: Layout): boolean {

        return placed.every((p) => !hit(curve, p));
      });
      return apart && free;
    }
