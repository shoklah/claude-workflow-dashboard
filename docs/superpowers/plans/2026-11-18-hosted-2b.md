# Hosted edward, plan 2b: viewers, the per-account labeller, admin settings, deletion and account:import

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On top of plan 2a's hosted edward: an account owner lets GitHub logins view their account through showing mode, labels with their own Anthropic key, can delete their account; the admin manages invites and accounts; a local history can be copied into an account.

**Architecture:** Showing mode's project list is kept apart from its switch, so a viewer's scope is the viewed account's kept list whatever its switch says. A session may name an account it views (a grant by GitHub login); the middleware then sets that account's file as the request's database, forces its scope and refuses every POST but switching back and signing out. Anthropic keys are sealed with AES-256-GCM under `EDWARD_SECRET` in the accounts database, and one label queue labels each account with its own client. Deletion and `account:import` act on the account's file through `accountFiles`.

**Tech Stack:** as plan 2a.

**Spec:** `docs/superpowers/specs/2026-11-18-cross-platform-and-hosted-design.md`, "Phase 3": viewers, labeller per account, bringing a local history into an account, after the move, account deletion, account settings, admin settings, and "Screens". Builds on plan 2a (`2026-11-18-hosted-2a.md`), merged first.

## Global Constraints

- Everything in plan 2a's Global Constraints holds. Server tests build their hosted app with 2a's `test/hosted-helpers.ts`; hosted `AppDeps` are built only by 2a's `hostedDeps` (Task 8), which a new hosted dependency joins.
- A task that adds a POST to `packages/web/src/api.ts` adds it to `CLAUDE.md`'s `src/api.ts` line in the same commit.
- `EDWARD_SECRET` is 32 random bytes, written as 64 hex characters in the data folder's `.env`; hosted mode refuses to start without it (2a's `hostedSettings` gains it).
- A stored Anthropic key is base64 of `iv (12 bytes) | tag (16 bytes) | ciphertext`, AES-256-GCM under `EDWARD_SECRET`; it is never returned (a response says only whether one is set), never logged, never in an error text, never in the reporter's env.
- A viewer sees an account's kept shown projects (none means every list is empty), every count includes every project, and every POST but `POST /api/view` and `POST /auth/signout` is refused with 403 while viewing; the views, `scopeOf`, `maskText` and `leaks` are reused unchanged.
- Viewers are granted by GitHub login (case-insensitive); a grant needs an invite only for that login to sign in.
- Removing an invite deletes that login's account's sessions and collector tokens, and `signInAccount` refuses an existing account whose login is neither invited nor the admin, so its sign-in ends at `/signin?error=refused`; its data stays until its account is deleted, and a re-invite needs a new collector token.
- Deleting an account removes its file (and `-wal`, `-shm`), its sessions, tokens, labeller settings and the grants it gave; the next sign-in of a still-invited login starts empty.
- The admin is `EDWARD_ADMIN`'s account only; `/api/admin*` answers 404 to anyone else; the admin can't delete their own account from the admin page.
- Local mode keeps its `.env` key and its labeller unchanged.

## Review Focus

1. **A viewer seeing a hidden project's name, path, branch or a session ID** through any route (the scope must come from the kept list even while the owner's showing mode is off): tested in Task 2 with `leaks` over every page route.
2. **A viewer changing the viewed account** (a POST to showing mode, seen, tokens, labeller, reset, delete while viewing): 403; tested in Task 2.
3. **A grant removed, an invite removed or an account deleted while a session is viewing it**: the next request falls back to the viewer's own account (grant gone) or is refused (invite gone); tested in Tasks 2 and 5.
4. **An Anthropic key leaking** (in `GET /api/account`, a log line when the API rejects it, the accounts database in clear): tested in Task 3.
5. **`account:import` over an account that already has data, or with a newer file**: refused, nothing copied; tested in Task 6.

## Spec flags (to the owner with the plan)

1. **`account:import` runs with the hosted server stopped:** the server keeps each account's file open once used, and swapping a file under an open handle would corrupt it. The command doesn't check for a running server; the README says to stop it first.
2. **A viewer's "Since you last looked" is the owner's:** the seen time lives in the account's file and a viewer can't move it, so the feed shows what came after the owner's last "Mark all seen", without the button.
3. **A removed invite deletes the account's collector tokens** (the spec's "refuses its collector tokens"), so a re-invited friend creates a new token; sign-in is refused at the callback, where the invite is checked, rather than on every request.
